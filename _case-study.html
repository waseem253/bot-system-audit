The problem

Teams that already run automation bots across departments want to scale further — but the seams between bots that are each individually "fine" are exactly where workflow gaps, silent failures, inflated metrics and lead leakage hide. An internal team stops seeing them; an external, evidence-based audit does not.

The deliverable

A structured audit in a fixed format so scope and output are unambiguous before any contract: 8 dimensions scored 0–5 (conversation design, workflow integrity, lead management, reporting accuracy, AI/LLM safety, reliability, scalability, security); a 9-phase methodology; a findings register (evidence, impact, fix, effort, 4-tier severity); and a remediation roadmap sequenced quick-wins-first so workflows are hardened before more automation is added.

Methodology

discovery + access ─▶ system mapping (every bot on one page) └─▶ heuristic review ─▶ transcript/log review ─▶ adversarial probing └─▶ data reconciliation ─▶ findings + severity ─▶ prioritised roadmap ─▶ readout

The audit is adversarial and evidence-based — the live system is driven through edge cases, handoffs, prompt-injection and failure paths to reproduce issues, not theorise them. The repo ships the full framework plus a polished, anonymised sample report so the exact deliverable format is visible up front.

Why it matters: an external reviewer who has shipped these systems in production probes yours independently — so you know exactly what to fix, and in what order, before scaling further automation.
